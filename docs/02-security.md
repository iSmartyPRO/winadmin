# Безопасность и доступ к API

## Аутентификация

Все эндпоинты, кроме `GET /health`, требуют заголовок:

```
X-API-Key: sp_<секрет>
```

UI хранит ключ в `localStorage` и шлёт его в том же заголовке (также поддерживается
cookie `sp_key`). Ключ проверяется по **SHA-256-хешу** — сырой секрет в БД не хранится и
показывается только один раз при создании.

## Вход учётками домена (Active Directory)

Если сервер в домене, вход учётками AD включён по умолчанию («Настройки → Подключение к домену»).
Каталог читается **учёткой компьютера** (служба работает как SYSTEM) по LDAP с подписью и
шифрованием (389) или по LDAPS (636); пароль для чтения не хранится.

- **Порядок проверки логина:** если есть локальный пользователь WinAdmin с таким логином —
  проверяется только его пароль; иначе — учётка домена (`ДОМЕН\пользователь`, `пользователь@домен`
  или просто `пользователь`).
- **Пароль домена принимается только по HTTPS или с самого сервера** (loopback). SSH-туннель к
  `127.0.0.1` сервера считается loopback. С сетевого адреса по HTTP — `400`.
- **Вход Windows (SSO)** — кнопка «Войти как текущий пользователь Windows» (`GET /auth/windows`):
  только **Kerberos**, NTLM не принимается. Открывайте WinAdmin по DNS-имени сервера; сайт должен быть
  в зоне «Интрасеть» браузера.
- **Доступ** даётся ролями, назначенными пользователю AD или его группам (по SID, с учётом вложенных
  групп). Без назначений — `403 «Нет доступа к WinAdmin»`.
- **Группы перечитываются** не реже раза в 5 минут. Если контроллер домена недоступен, используются
  последние известные группы до 15 минут, затем сеанс завершается (`401`). Отключённая или удалённая
  в AD учётка теряет доступ не позже чем через 5 минут; обновить сеанс (refresh) она не может.
- **Контроллер домена недоступен** — вход доменом отвечает `503`, локальные учётки работают.
- Назначение «Администратор» на пользователя или группу AD считается действующим, только пока каталог
  подтверждает учётку (включена) или группу (существует).

## Управление AD (модули «Пользователи AD», «Папки»)

Изменения в AD вносит **учётка записи** («Настройки → Active Directory: управление»):

- **Служебная учётка** (рекомендуется) — отдельный пользователь AD с правами, делегированными только на нужные OU.
  Пароль хранится зашифрованным (AES-256-GCM, ключ под DPAPI машины) и через API не возвращается.
- **Учётка службы WinAdmin** — без пароля. На контроллере домена это учётка компьютера DC, то есть права
  администратора домена; используйте только осознанно.

Запись выполняется только по зашифрованному каналу (LDAP 389 с подписью и шифрованием или LDAPS 636).
Перед любой записью проверяется, что объект лежит в корневой OU, его проект не скрыт и входит в область
прав оператора. Сгенерированные пароли показываются оператору один раз и не пишутся в журнал.

**Проверка окружения** (`platform.environment.check`, «Администрирование → Проверка окружения») показывает
готовность домена, корневой OU, учётки записи и шифрования канала с подсказками, что исправить. Быстрая
проверка повторяется в фоне раз в час; в журнал аудита попадает только смена итогового статуса
(`environment.status`).

### Модуль «Пользователи AD»: что делегировать учётке записи

| Действие | Право в AD |
|---|---|
| Атрибуты и фото | Write Property на атрибуты из настроек модуля и `thumbnailPhoto` для объектов user в `OU=Users` проектов |
| Сброс пароля | Reset Password на объекты user в `OU=Users` проектов |
| Перенос между проектами | Create/Delete User objects на `OU=Users` проектов (источник и цель) |
| Увольнение / восстановление | Write members на группу уволенных и «Пользователи домена»; Write `primaryGroupID`; перенос в OU уволенных и обратно |

«Проверка окружения» показывает, каких из этих прав не хватает. Уволенные пользователи (в OU уволенных) видны и
доступны всем, у кого есть `ad-users.offboard`; при восстановлении целевой проект должен входить в область.

### Модуль «Папки»: что делегировать учётке записи

| Действие | Право |
|---|---|
| Участники Full/Read | Write members на группы `sg_*` в OU проектов |
| Новая папка — группы | Create Group objects на OU групп проектов (по умолчанию — OU проекта) |
| Новая папка и «Исправить права NTFS» | «Изменение разрешений» (или «Полный доступ») на корне шары; создание папок в ней |

Служебная учётка обращается к файловому серверу через `LogonUser(NEW_CREDENTIALS)`: локальная сессия остаётся
учёткой службы, сетевые обращения идут от имени служебной учётки. Правила NTFS добавляются по SID групп
(Full → Modify, Read → ReadAndExecute, с наследованием), чужие правила не изменяются. Модуль меняет участников только
групп с префиксом модуля, лежащих в проектах под корневой OU и в области оператора.

## Лимит попыток входа

`POST /auth/login`: не более 5 неудачных попыток в минуту для пары (IP, логин) и 20 — для IP;
сверх лимита — `429` с заголовком `Retry-After`. Время ответа для несуществующего логина
выровнено с неверным паролем. Аудит: `auth.login`, `auth.login.failed`, `auth.windows`
(пароль не записывается).

## Права и роли

Доступ задаётся **ролями**. Роль — набор прав вида `модуль.действие`; для модулей с
областью (Active Directory) — ещё и список OU. Роли назначаются пользователям WinAdmin и
API-ключам (раздел **Роли**, API `/api/v1/roles`, `/api/v1/role-assignments`).

| Право | Доступ |
|-------|--------|
| `system.read` | Информация о системе, метрики, диски |
| `services.read` / `services.manage` | Список служб / управление |
| `processes.read` / `processes.manage` | Список процессов / завершение |
| `printers.read` / `printers.manage` | Список принтеров / управление |
| `power.manage` | Перезагрузка/выключение |
| `eventlogs.read` / `eventlogs.manage` | Журналы Windows / исключения учётных записей |
| `software.read` / `software.manage` | Программы и обновления / удаление и откат |
| `platform.*` | Пользователи, роли, модули, API-ключи, аудит, сеть, подключение к домену |

Встроенная роль **«Администратор»** даёт все права, включая права будущих модулей.
Выдавать роли можно только в пределах собственных прав (делегирование без повышения).

**Принцип наименьших привилегий:** выдавайте внешним системам только нужные права.
Например, системе мониторинга — роль с `system.read`; системе оркестрации, которая
перезапускает службу, — с `services.manage`.

## Управление ключами

- UI: страница **API-ключи** (`/cp/apikeys`) — создание (выбор ролей и срока действия),
  показ секрета один раз, отзыв.
- API: `GET/POST/DELETE /api/v1/apikeys` (право `platform.apikeys.manage`).
- Отозванный или просроченный ключ немедленно перестаёт работать (→ `401`).

## Аудит

Каждое управляющее действие и операции с ключами пишутся в журнал аудита:
кто (имя ключа), что (action), объект (target), результат, детали, source IP, время.

- UI: страница **Аудит** (`/cp/audit`).
- API: `GET /api/v1/audit` (право `platform.audit.read`).

## Сетевые меры

- **Rate limiting:** 120 запросов в минуту на ключ/IP (фиксированное окно) → `429`.
- **HTTPS** — см. раздел ниже; перенаправление с HTTP включается отдельным портом (`httpRedirectPort`).
- **CORS** по умолчанию закрыт; разрешённые источники задаются в конфиге:

  ```json
  { "WinAdmin": { "CorsOrigins": [ "https://portal.example.com" ] } }
  ```

## HTTPS

В режиме «Сеть» без HTTPS пароли, токены и cookie идут открытым текстом, а **пароль домена по сети не
принимается** (`400`). Включите HTTPS: **Настройки → Сеть → HTTPS** или из консоли администратора:

```powershell
.\WinAdmin.exe network https --enable --thumbprint <отпечаток> [--store LocalMachine|CurrentUser]
.\WinAdmin.exe network https --enable --pfx C:\certs\panel.pfx --pfx-password "..."
.\WinAdmin.exe network https --enable --self-signed [--dns panel.corp.local]
.\WinAdmin.exe network https --redirect-port 80      # 0 — без перенаправления
.\WinAdmin.exe network https --show
.\WinAdmin.exe network https --disable               # аварийный путь, если панель недоступна
```

- **Сертификат:** из хранилища «Личные» (`LocalMachine\My` — рекомендуется; служба работает как SYSTEM),
  файл PFX или самоподписанный, созданный WinAdmin (RSA 2048, 2 года, SAN: полное и короткое имя
  компьютера, `localhost`, дополнительные имена). Самоподписанный хранится в `keys\https.pfx`.
- **Секреты:** пароль PFX хранится в `network.json` только зашифрованным (`ISecretProtector`), API
  возвращает лишь признак «задан»; пароль самоподписанного — случайный, зашифрован в `keys\https.pfx.password`.
  `--pfx-password` в командной строке виден в списке процессов и истории консоли — вводите в доверенной консоли.
- **Перед применением** проверяется: сертификат найден, есть закрытый ключ, срок действия начался и не истёк,
  назначение «Проверка подлинности сервера» (если EKU задан). Иначе `400` с причиной.
- **Применение** — как смена порта: без перезапуска, с автоматическим откатом, если через 10 с порт не
  слушается или TLS-рукопожатие с `127.0.0.1` не удалось.
- **Только HTTP/1.1** на HTTPS-порту: вход Windows (Negotiate/Kerberos) привязан к соединению и по HTTP/2 не работает.
- **HSTS** `max-age=31536000` (без `includeSubDomains`) — только в HTTPS-ответах. Браузер запоминает его
  для имени сервера на год: после выключения HTTPS он продолжит открывать `https://` для этого имени
  (на любых портах). Браузеры игнорируют HSTS при ошибке сертификата (самоподписанный без доверия).
- **Cookie `wa_refresh`** по HTTPS всегда `Secure`.
- **Перенаправление:** необязательный HTTP-порт отвечает `308` на тот же путь по HTTPS; брандмауэр
  открывает его тем же правилом `WinAdmin (managed)`.
- **Самоподписанный сертификат** вызовет предупреждение браузера. Чтобы его не было, добавьте сертификат
  в «Доверенные корневые центры сертификации» на клиентах (GPO) или используйте сертификат корпоративного ЦС.
- **Вход Windows (SSO) по HTTPS:** открывайте панель по **DNS-имени** сервера (`https://srv01.corp.local:8443`),
  а не по IP; имя должно быть в SAN сертификата; добавьте сайт в зону «Местная интрасеть».
- **Проверка окружения** `platform.https`: HTTPS выключен в режиме «Сеть» или сертификат истекает менее чем
  через 30 дней, или имени компьютера нет в SAN — предупреждение; сертификат не найден, без ключа, истёк — ошибка.
- Если сертификат пропал или истёк, HTTPS **не** выключается сам (иначе защита тихо пропала бы):
  ошибка в журнале и в проверке окружения; восстановить доступ — `network https --disable` или выбрать другой сертификат.

## Рекомендации по харденингу

1. Ограничьте доступ к порту приложения межсетевым экраном (только доверенные системы).
2. Используйте HTTPS с валидным сертификатом.
3. Храните БД (`WinAdmin.db`) вне каталога приложения, доступ — только сервисной учётке.
4. Удалите `bootstrap-key.txt` после первичной настройки.
5. Задавайте срок действия (`expiresAt`) для интеграционных ключей и ротируйте их.
6. В продакшене ограничьте доступ к `/swagger` (обратный прокси/правила IIS) при
   необходимости.
