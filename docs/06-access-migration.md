# Переход с портала Access на WinAdmin

WinAdmin заменяет портал Access (ASP.NET + PostgreSQL). Настройки и права доступа Access
переносятся командой `import access`; после проверки Access выводится из эксплуатации.

## Что переносится

| Access | WinAdmin |
|---|---|
| `app_settings.ldap_path` | Корневая OU («Настройки → Active Directory») |
| `ad_service_domain` + `ad_service_username` | Учётка записи (`ДОМЕН\имя`) |
| `ad_service_password` | Пароль учётки записи — **только** с `--import-service-password`, хранится зашифрованным |
| `app_settings.fired_users_group` | Модуль «Пользователи AD» → группа уволенных |
| `excluded_ous` | Скрытые OU (объединение с уже заданными) |
| `terminated_user_ous` (OU «по умолчанию для деактивации», с DN) | Модуль «Пользователи AD» → OU уволенных |
| `role_principals`: `super_admin` | Роль «Администратор» |
| `role_principals`: `admin` | «AD: администраторы пользователей» + «AD: администраторы папок» |
| `role_principals`: `hr` | «AD: отдел кадров» |
| `portal_users` (активные) | Те же роли для пользователя AD |
| `audit_log` | Журнал аудита WinAdmin, действия `access.*` — только с `--audit` |

Назначения ролей делаются **по SID**: DN/логин из Access ищется в AD. Не нашлось — строка
«Не найдено в AD» (учётка удалена или переименована). Роли-шаблоны создаются, если их нет; модули
при этом **не включаются**.

**Не переносятся** (в отчёте — «Не импортируется»): локальные учётки `local_users` (другой формат
хеша — создайте заново `WinAdmin.exe user add`), метаданные и рассылки проектов, Exchange,
ключи API (Яндекс.Карты), неактивные `portal_users`, OU уволенных без признака «по умолчанию».
Из журнала удаляются поля с паролями (`newPassword` при активации и т. п.).

## Как запустить

Команда выполняется на сервере WinAdmin из консоли администратора. Нужен доступ к PostgreSQL Access
(только чтение) и рабочее «Подключение к домену» в WinAdmin.

1. **Остановите службу WinAdmin** — служба держит настройки в памяти и затёрла бы импорт
   при следующем сохранении:

   ```powershell
   Stop-Service WinAdmin
   ```

2. **Отчёт без изменений** (dry run). Пароль PostgreSQL удобно передать переменной, чтобы он
   не попал в историю команд:

   ```powershell
   $env:WINADMIN_ACCESS_PG_PASSWORD = Read-Host "Пароль PostgreSQL Access"
   .\WinAdmin.exe import access --connection "Host=pg01;Port=5432;Database=access;Username=access"
   ```

   Для каждой строки — что, откуда, куда и статус: «Будет создано», «Пропущено — уже есть»,
   «Конфликт», «Не найдено в AD», «Не импортируется»; внизу — итог.

3. **Разберите отчёт:**
   - «Конфликт» — в WinAdmin уже задано другое значение. Оставьте как есть или повторите с
     `--overwrite` (заменит **все** конфликтующие значения).
   - «Не найдено в AD» — проверьте учётку/группу в AD; при необходимости назначьте роль вручную.
   - «Не импортируется» — перенесите вручную, если нужно (примечание подскажет, как).

4. **Импорт:**

   ```powershell
   .\WinAdmin.exe import access --connection "Host=pg01;Database=access;Username=access" --apply --audit --import-service-password
   ```

   - `--audit` — перенести журнал (можно запускать повторно: продолжит с последней записи).
   - `--import-service-password` — перенести пароль служебной учётки. Без флага введите пароль в
     «Настройки → Active Directory» (так безопаснее, если пароль заодно меняется).
   - Повторный запуск безопасен: уже перенесённое — «Пропущено — уже есть».
   - В журнал WinAdmin пишется запись `import.access` с итогом.

5. **Запустите службу**: `Start-Service WinAdmin`.

## Чек-лист вывода Access из эксплуатации

- [ ] Импорт выполнен (`--apply`), отчёт без неразобранных «Конфликт» и «Не найдено в AD».
- [ ] Включены модули «Пользователи AD» и «Папки» («Модули»), «Проверка окружения» — без ошибок.
- [ ] Проверен вход: администратор (бывший `super_admin`), сотрудник кадров (группа `hr`),
      пользователь из `portal_users` — у каждого нужные разделы и только они («Роли»).
- [ ] Локальные учётки Access, которые ещё нужны, созданы заново (`WinAdmin.exe user add`).
- [ ] Сайт Access в IIS остановлен (сайт и пул приложений), ссылки/DNS переведены на WinAdmin.
- [ ] Сделан бэкап PostgreSQL Access:
      `pg_dump -h pg01 -U access -Fc -f access-final.dump access`.
- [ ] Удалён пароль adService из БД Access:
      `UPDATE app_settings SET ad_service_password = '' WHERE id = 1;`
      (в бэкапе он остаётся — храните бэкап как секрет или смените пароль adService в AD).
- [ ] Через 1–2 недели без обращений — удалить сайт, пул и (по политике хранения) БД Access.
