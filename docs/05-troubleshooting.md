# Диагностика

## Перезагрузка/выключение возвращает ошибку (код 1314 / привилегия недоступна)

Причина: рабочий процесс не имеет привилегии `SeShutdownPrivilege` или прав
администратора. Решение: пул приложения должен работать под учётной записью с правами
локального администратора и правом «Завершение работы системы»
(см. [01-deploy-iis.md](01-deploy-iis.md), раздел «Модель привилегий»).

## Остановка службы возвращает «Не удалось выполнить действие»

Причина: недостаточно прав у учётной записи пула, либо служба не допускает остановку
(`canStop = false`), либо есть зависимые службы. Проверьте `canStop` в `GET /services` и
права учётной записи.

## Пустой список дисков/служб или ошибки WMI

- Убедитесь, что служба **Windows Management Instrumentation (Winmgmt)** запущена.
- Учётная запись пула должна иметь доступ к WMI (по умолчанию у администраторов есть).
- При повреждении репозитория WMI: `winmgmt /verifyrepository`.

## Метрики CPU всегда 0%

Первый вызов `PerformanceCounter.NextValue()` всегда возвращает 0 — это нормально;
значение появляется со второго опроса. UI опрашивает метрики каждые 3 секунды.
Если значения постоянно 0 — проверьте счётчики производительности:
`lodctr /R` (пересборка счётчиков), затем перезапуск.

## 401 на все запросы

- Проверьте заголовок `X-API-Key` и сам ключ (не отозван, не просрочен).
- Сразу после установки ключей ещё нет — используйте стартовый ключ из
  `bootstrap-key.txt`.

## 403 при наличии ключа

У ключа нет требуемого scope. Выдайте нужный scope или используйте ключ со scope `admin`.

## 429 Too Many Requests

Превышен лимит (120 запросов/мин на ключ/IP). Снизьте частоту опроса или распределите
нагрузку. Лимит настраивается в `Program.cs` (`PermitLimit`, `Window`).

## База данных: «no such table» / данные не сохраняются

- Убедитесь, что задан корректный `WinAdmin:DatabasePath` (непустой путь к файлу).
  Пустая строка приводит к временной БД, которая теряется между подключениями.
- Учётная запись пула должна иметь права на запись в каталог БД.

## Приложение не стартует под IIS (502.5 / ANCM)

- Установлен ли **ASP.NET Core Hosting Bundle**? После установки — `iisreset`.
- Включите stdout-лог в `web.config` (`stdoutLogEnabled="true"`) и смотрите файл в
  `.\logs\stdout*`.
- Проверьте, что пул в режиме **No Managed Code** и `processPath` указывает на
  `.\WinAdmin.exe`.

## SPA не открывается (видна заглушка/404)

Соберите фронтенд: `npm --prefix web run build` (кладёт файлы в
`src/WinAdmin.Api/wwwroot`), затем переопубликуйте приложение.
